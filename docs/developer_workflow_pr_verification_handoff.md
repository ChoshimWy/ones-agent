# Draft PR 人工验证交接

## 默认流程

本地测试通过、代码审查无待修复问题后，尚未执行的外部验证不再阻止生成审批包。
操作者审批只授权提交、推送和创建 **Draft PR / Draft MR**，不授权合并或发布。

1. 审查继续区分代码问题与外部验证。代码问题仍回修；失败测试、验证失败/错误、证据过期仍阻断。
2. 仅 `manual`、`ready`、`waiting_environment` 可交接。验证记录不伪造为 `passed`。
3. 审批指纹包含待验证项、验收要求、环境能力、源码快照和 PR 清单。待验证范围改变须重新审批。
4. 推送实际提交后，写入 `ones-agent/external-verification` 的 pending 状态；以原生草稿方式创建 PR。
5. 恢复不确定的 PR 创建结果时，同时核对草稿状态、源/目标分支、任务标记和提交 SHA。
6. 全部受影响仓库 PR 交付并回写 ONES 后，任务进入 `WAITING_PR_VERIFICATION`（等待 PR 人工验证），不标为 `COMPLETED`，不再重复修复或审查。

每个有变更的仓库都带完整跨仓库检查清单和自身实际提交 SHA。未修改仓库仍受原审批快照约束，不人为创建空提交。

## 旧任务

缺少修复前失败复现记录的缺陷任务，可在默认模式下创建 Draft PR。该证据缺口作为单独待验证项写入清单、审批指纹和审批确认窗口；既有修复后测试、冻结复现文件哈希、代码审查及快照一致性检查不放宽。缺失记录与已有但不合格的记录不同：已有记录仍必须满足原有失败类型和命令绑定规则，不能把失败/错误记录改成“缺失”放行。

旧的“缺少修复前失败复现记录”暂停任务点击“重新检查审批条件”，复用既有 Review 并重新核对证据，不重复运行 AI 审查。PR 审核人应优先在隔离的历史版本补验，无法补验时明确评估证据限制；不得虚构历史测试或宣称已证明修复有效。严格模式仍阻断缺少基线的审批。

已因缺少环境暂停的任务，在“环境验证”窗口选择“转交 PR 人工验证”，可重新使用原测试及审查证据生成审批包；随后点击“审批并创建 Draft PR”。
该交接操作本身不推送代码。命令行也可恢复旧任务，再显式审批。

需要保留严格的 PR 前验证模式时，工作流配置 `publishing.defer_external_verification_to_pr` 设置为 `false`；默认 `true`。
关闭该配置后旧草稿审批也不能绕过前置验证。已有审批指纹没有待验证字段时保持兼容。

## 仓库管理员需要配置的合并门禁

**pending 状态不是必需检查规则本身。** 本工具不修改仓库级分支保护，也不会声称已核验管理员设置。

- GitHub：在目标分支保护 / ruleset 中要求 `ones-agent/external-verification` 通过；将检查来源绑定到可信验证集成（如适用），限制规则绕过和直接推送。
- GitLab：目标分支需受保护，并启用要求流水线成功的合并检查。确保该外部验证状态属于合并所检查的当前提交流水线，尤其是同时存在 MR / 分支多条流水线的项目；不能仅依赖标题中的 Draft。
- 草稿状态本身阻止直接合并，但有权限的人可以转为 Ready；不能用草稿替代上述仓库规则。
- 实际发布仍由发布流水线门禁负责，不能因为 PR 交付或合并就宣称发布包通过实机验证。

当前实现会发布 pending 检查，不会把 PR 复选框、评论或 AI 总结自动识别成通过证据，不会自动转为 Ready、合并或发布。
若仓库没有受信任的验证回填集成，需由维护者先接入；不要直接取消 pending 检查来放行。

## PR 审核人的操作

对清单逐项在指定平台/设备完成验证，在 PR 中记录操作者、实际提交 SHA、环境、步骤、预期/实际结果及日志/截图。
验证步骤或验收标准为空的旧任务，先补充标准，不能直接打勾视为通过。
由受信任的人工验证/CI 集成对**同一提交 SHA**回填该检查结果；有任一项未通过则继续 pending 或标失败。
代码、依赖或制品变化后重新验证新提交/制品。发布包 SHA、架构、成对安装等只能基于实际制品确认。

本地任务保留交接时的待验证快照供审计；本版本尚不订阅 PR webhook，也不自动回填 PR 后的验证结果。
人工验证和后续合并审核在 PR 平台完成，不要求本地任务循环执行 review。

## 核验范围

回归覆盖单仓库/多仓库 Draft 交付、审批快照绑定、原严格验证路径、失败拒绝、幂等恢复、原生 Draft API 参数及 pending 状态。
测试使用隔离临时目录和模拟 HTTP，不代表已在用户仓库创建 PR、配置分支保护或完成 macOS/GPU 实机验证。

API 依据：[GitHub Pull requests](https://docs.github.com/en/rest/pulls/pulls)、[GitHub Commit statuses](https://docs.github.com/en/rest/commits/statuses)、[GitLab Draft MR](https://docs.gitlab.com/user/project/merge_requests/drafts/)、[GitLab Commit status](https://docs.gitlab.com/api/commits/#set-commit-pipeline-status)。
